Projects

Sector news pipeline

Five Airflow DAGs collect news from more than a hundred outlets twice a day, with five scraping strategies that follow what each source offers, from RSS feeds and XML sitemaps of public bodies to listing page navigation, multi-sector portals and sites that only render with JavaScript, collected through Selenium in a pool on Selenium Grid. Cleaning standardises irregular date formats, strips title and footer noise and deduplicates by title, and a local language model classifies each item into one or more sectors, in batches, for each sector's weekly bulletin. Every discard leaves a trace, so a source that goes down becomes an alert, an empty batch is retried and a rejected deal goes to an audit table.

Deal extraction

The second stage turns classified news into a structured database of deals, covering mergers and acquisitions, venture capital rounds and other corporate transactions. Primary screening combines a regex pattern score on the headline with a multilingual mDeBERTa-v3 zero-shot classifier running on GPU, with calibrated thresholds, and only what passes moves on to the LLM call, which extracts the parties, value, currency, sector, status and countries involved as JSON validated against a closed schema. A cascading judge checks whether what changes hands is a company rather than a single asset, whether the deal belongs to the period and whether the article brings a new fact, and semantic deduplication recognises different spellings, swapped roles and status changes of the same deal.

Python · Apache Airflow · PostgreSQL · Selenium Grid · Ollama · mDeBERTa zero-shot on GPU · Groq · LangChain · Object storage · SMTP · Report automation

Public tender monitor

Maps the public tenders a company can bid for and measures how close each one is to the services it offers. A daily Airflow pipeline sweeps 20 public procurement portals and organises everything in a Medallion architecture on Postgres. In the bronze layer each record gets a fingerprint derived from its source identifier, which rules out reprocessing, the silver layer picks the best date and the best value among those each source provides, and the gold layer downloads the attached PDFs, extracts the text and applies the filter again. The relevance grade combines, with different weights, domain keywords, a zero-shot classifier on GPU and an LLM assessment. Each collector fails explicitly when it hits a block or an invalid response, and the output is a spreadsheet by email and a FastAPI dashboard.

Apache Airflow · mDeBERTa zero-shot on GPU · Groq · PostgreSQL · Object storage · FastAPI

Macroeconomic dashboard

Thirty-eight series from five public sources live in DuckDB, covering prices, credit, the external sector, activity and public accounts, and each derivation is validated against the official series before it enters, to the point that the rebuilt IPCA matches within about 0.005 percentage points at most. The pipeline draws a chart per indicator and uses an LLM to combine the reading of each chart with the reading of the already classified news on the same theme, quoting only numbers the database computed, because the model narrates and does not calculate. The delicate part is time alignment, since each observation refers to a reference period that is usually released weeks later, while the news is dated by publication and often comments on the figure on release day. The join uses the series reference period and last-month and last-week windows over the publication date, so each theme's synthesis matches the number with the news that actually discusses it.

Python · DuckDB · FastAPI · Jinja2 · Groq · Docker

Classic local RAG and index-based RAG with Claude

The classic RAG runs entirely on in-house infrastructure, because it was designed for sensitive documents that cannot leave the company, and it answers citing document, sector and date for each passage. PDFs become Markdown with opendataloader, and a local vision model describes images and charts, inserting the description at the exact spot on the page it came from. Chunking cuts at headings, in passages of 40 to 220 words with a 40-word overlap between neighbours, never splits tables or described images and drops tables of contents. Embeddings come from bge-m3 and are stored in pgvector, and retrieval is hybrid, joining vector search by cosine similarity with keyword search and favouring passages that rank well in both. An evaluation framework with Ragas and MLflow compares models, chunking parameters and prompts with faithfulness, relevance and precision scores.

Index-based RAG

The archive index is a RAG that, instead of retrieving passages by vector similarity, queries a catalogue of records describing each file on the network share, and answers which files exist on a subject, from which source and from when. Since it does not need to keep the content inside the infrastructure, it uses Claude to navigate the catalogue. The inventory samples each file according to its type, reading the delimiter and first lines of a CSV, the sheets of a spreadsheet, the text of slides and of the first PDF pages and the code of notebooks, and sorts everything into four curation levels. Catalogue search is BM25 with per-field weights, and extraction is incremental, so a file is only reprocessed when it changes or when the extractor version changes. Each file becomes a record with source, confidentiality, period and columns, served over MCP and through a question page.

pgvector · bge-m3 · local VLM and LLM · Claude · PostgreSQL · opendataloader · Ragas · MLflow · MCP · FastAPI

Techniques of top Kaggle competitors

Collects the machine learning techniques used by the winners of Kaggle competitions, processing in bulk, with language models, the public code of the teams at the top of the leaderboard. Each notebook goes whole to an LLM, together with the competition description, and comes back as an analysis in four numbered sections. A second step turns that analysis into three tables, with the techniques used, the contrasts between common practice and the expert's choice, and a glossary, and the output is validated with Pydantic. A contrast is only recorded when the analysis itself describes both approaches, the one most competitors used and the one the winning team adopted, which keeps the model from filling in common practice by guesswork, and an audit script checks every extracted row against the source text.
